## Motion design contract

Give each page three clear depth planes. Background photographs travel slowly, framed editorial media moves independently with its own scroll range, and text and controls provide a stable reading plane. Use a clear, visible motion beat in the hero, the first proof section, a mid-page media section and the closer. Supporting sections use smaller accents or stillness. The ranges below are starting values for testing at 1512 px width. Use about half the travel on phone, shorten it further in landscape, and cap the 4K increase around 1.4× until the owner reviews it on the display. Depth comes from speed differences, contrast and framing.

## Motion implementation

1. **Separate layout from paint.** Each scene gets an untransformed measurement wrapper, a clipping frame, and a visual child. A bounded image transform uses enough overscan for the largest shift so no blank edges show. Keep section anchors, text, captions, link hit areas and focus rings in normal flow. Use overlapping visual shoulders and masks for page transitions. Avoid scaling or fading a full section that still has visible copy or focusable controls. Keep existing section IDs, PageNav labels, action rows, contact modal, and shareable fragment links.
2. **Choose one writer for each layer.** Prefer named CSS view timelines where the complete feature set works. For fallback and dock state, schedule one passive-scroll frame per route, batch geometry reads before writes and update nearby scenes only. Reuse the established native/fallback approach where it fits. The current shared stylesheet also translates `.sec-head` and `.slide-media`; avoid applying a second effect to those same nodes and preserve their behavior elsewhere. Tune the same endpoints across the native and fallback paths. [Shared CSS](../sites/hey-this-is-andrew/src/styles/parallax.css#L10), [current fallback](../sites/hey-this-is-andrew/src/lib/parallax.ts#L28).
3. **Use progress, not a timer, to drive the scroll.** Clamp progress against the stable wrapper's viewport entry and reading/exit positions. Use one monotonic curve per beat. The same scroll point must yield the same final pose after moving in either direction. Let a small number of slow decorative layers ease briefly if profiling supports it; never put a CSS transition on values rewritten every frame or delay a focus/anchor state to chase the animation. Use compositor-friendly translate/scale/opacity on visual children and profile real devices. Avoid animated blur, shadows, layout dimensions, permanent `will-change`, scroll interception and persistent idle loops.
4. **Unify the dock and anchor contract.** Compute from the visible header, an explicit settled dock size and stable action/heading positions. Keep CTA contrast until handoff. Set inert as the dock goes out of view and return focus to an actually visible element if focus was inside. Coordinate with the pending PageNav and BaseLayout changes so cold loads, same-document fragments, click-to-jump, Back/Forward, and closer landing share the clearance. Keep the closer inside the accessible scroll range at 4K. No hardcoded laptop height should dictate 4K offsets. [PageNav](../packages/ui/src/PageNav.astro#L769), [fragment handler](../sites/hey-this-is-andrew/src/layouts/BaseLayout.astro#L227).
5. **Handle lifecycle and accessibility up front.** With reduced motion or JS unavailable, render complete static content. Make reduced-motion jumps instant and reset all style state when the preference changes. Invalidate measurements after resize, orientation, fonts, image load and publication card updates. Reserve image and card geometry before fetching. On teardown, remove listeners, observers and pending frames. Verify that repeated initialization and navigation never stack controllers. On iOS, check toolbar changes and keep pinned scenes off short landscape layouts.

### Publisher and consumer

1. **Publisher agent, in the real HQ repo.** Add a small versioned public JSON route, proposed `/api/latest-posts.json`. Derive from `getAllFeedItems()` and the same eligibility as the public feed. Exclude drafts, hidden/unlisted records, events, shorts and livestreams outside the public Videos feed, future timestamps, invalid canonical targets and duplicates. Reuse article canonical-link and card-image logic. Use `isoDate` / `publishedAt` first and HQ's stable feed order for a date tie. A video card can land on HQ's `/feed?play=<youtubeId>` when the card exists in the public feed, using its established click-to-play experience. Test that route and retain a canonical video fallback if the HQ destination cannot cue it. Keep articles linked to their canonical story. [Unified feed](https://github.com/HeyThisIsAndrew/BeUnconventionalHQ/blob/main/src/lib/feed-items.ts), [video deep links](https://github.com/HeyThisIsAndrew/BeUnconventionalHQ/blob/main/src/pages/feed/index.astro), [card images](https://github.com/HeyThisIsAndrew/BeUnconventionalHQ/blob/main/src/lib/card-images.ts).
2. **Contract.** Return `version`, an optional publication build ID, and up to two ordered items with stable ID, kind, title, absolute HTTPS canonical URL, ISO published time, and a validated image descriptor with src, optional candidate widths, dimensions and optional trustworthy alt or focal point. Keep publisher-side image fallback handling and use actual dimensions for supplied renditions. Test remote artwork from the consuming origin. Keep article and video cards available if their thumbnail fails; use a neutral, branded fallback within the same frame. Avoid returning article HTML, credentials or analytics data. Verify the deployed endpoint has the correct JSON content type, conditional cache behavior and an allowed Origin for the personal site. Use an ordinary credential-free GET and an initial five-minute freshness budget.
3. **Consumer agent, in the personal-site repo.** Fetch and validate the manifest with a bounded timeout during the build for two crawlable card links and stable first paint. Retain an explicitly managed last-known-good snapshot or, on first build without data, render the Publication intro and an “Explore the feed” link. The build should still work offline. Revalidate near the section once per page visit from the live manifest. No polling loop. Preserve the rendered order and geometry on refresh. Avoid replacing a focused/hovered card or shifting the current scroll scene; defer the swap until it is safe. Failed requests or an unknown schema keep the seeded cards within a documented stale window. Use an initial 24-hour stale window, after which the consumer can show the feed link until it confirms the current cards. A valid authoritative empty response clears withdrawn items and shows the feed link immediately. An initial rollout can ship with build-only refresh plus a defined rebuild trigger if CORS is pending, but final acceptance requires the two posts to update after HQ publishes without a new personal-site code change or manual edit. No embed loads until the user follows the video link.
4. **Prove it end to end.** In a fixture, publish a newer eligible video, let the consumer refresh without rebuilding the personal page, and verify that it becomes card one and displaces the older card. Repeat with two articles, two videos, timestamp ties, an unpublished item, a duplicate, missing image, one/zero items, offline, timed-out fetch, bad schema and failed cross-origin fetch. On production, compare the API payload, its destination URLs and the visible two cards against the publisher. Check thumbnails for real loading, aspect ratio and focal crop at phone and 4K widths. Keep the feed CTA useful with JS disabled.

- **Motion quality.** Profile normal scroll, a fast fling, reverse scroll and dock handoff on a physical phone and the owner's 4K screen. Compare traces before and after. Aim for no route-owned long tasks over 50 ms during a representative scroll and motion callback p95 under 4 ms on the measured midrange device. Check filmstrip continuity and dropped frames; avoid promising a frame rate solely from automation. Verify idle/offscreen motion does no ongoing work and decorative layers stop under reduced motion.
